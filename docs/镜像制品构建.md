# 镜像制品构建

runtime 底座固定 DSH 安装，但其中的 Studio 通用 Host 也必须使用本轮审查后的制品。仅更新个人助理插件不足以修复通用 Host 的托管运行时准入规则。

使用 Node 22，在修复后的 Studio 工作树先执行 `npm pack`，然后在个人助理项目构建：

```sh
npm run build:client
PA_STUDIO_HOST_TARBALL=/绝对路径/kingsoftcloud-agentkit-studio-0.0.2.tgz npm run build:artifacts
```

runtime tar 包含 `host/agentkit-studio.tgz`，以及独立插件的 Host、客户端与 API。构建镜像前，将两个 artifact 的 SHA-256 写入 images 仓库对应的 `sources.lock.json`，并将 Studio 的 Git commit 和 tarball SHA-256 写入 runtime lock 的 `studioHostArtifact`。

Dockerfile 在安装 Studio 通用 Host 前核对 tarball 摘要，安装后执行一次 personal-assistant manifest 的真实解析。校验失败会使真实镜像构建失败，不允许只凭源码白名单或 Dockerfile 语法检查判断启动可用。Studio 对个人助理完成严格身份校验后，交给独立插件监听 8080，不再启动通用 Studio frozen HTTP 服务。
