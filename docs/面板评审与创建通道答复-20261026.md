个人助理页面仍由本插件提供。Studio 只保留通用宿主、插件中心与精选插件条目，不新增个人助理产品页面。

本次调整：

- 页面不展示网关地址、密钥配置输入或开发配置指引。凭据继续留在 Host；页面只读取连接状态。
- 正常从云端真实目录中选择助理。目录协议不支持时提供上述兼容期诊断入口；其他未开通、空目录和鉴权错误不提供手填入口。状态刷新不冒充创建实例。

Lead 所有的 `scripts/build-client.mjs`、`package.json`、`docs/本地安装与云电脑连接.md` 未由本次实现修改。构建器当前在进程开始时生成时间戳，因此同一次 watch 会话的多次重建沿用该时间戳；页脚可以确认该构建会话，不能独自区分会话内每次重建。

## 创建通道 503 的结论

已定位指定失败记录 `ar-20261025221906-pa-e2e-0`：有模型 key，但 `OPENAI_BASE_URL` 与 `model_config.api_base` 均为空；BuildJob 必然拒绝，原文为 `personal-assistant requires an authorized model endpoint and API key`。此前错误被泛化成「同一 operation 重试」503，日志又只留下 `%T`；Server 同步失败后仍返回成功，是另外一个返回边界缺陷。

本方相同入口的 0.1.2 实例 `ar-20261025222804-4df266ad` 创建成功并达到双容器 Ready，因此不是所有账号/请求全局失败。最初对失败 ID 的 404 来自账号作用域；随后已按指定 ID 找到记录并完成脱敏对照，没有要求 Lead 提供 AK/SK。

已灰度 dev：runtime-service 增加原始错误与阶段、确定性配置错误返回 400；Server 增加指定协议的同 operation 有界重试、缺模型 endpoint 的创建前检查，以及同步失败不再返回 Code 0。真实缺 endpoint 请求返回 HTTP 400 / Code 400，RequestId `req-20261025231456-hvmjbs`，同名 Agent 记录请求前后均为 0。证据及镜像摘要见《创建通道核查-20261025.md》。这些修复不代表所有 503 都已定位，后续瞬时错误仍需按 request ID 和原始阶段追查。
