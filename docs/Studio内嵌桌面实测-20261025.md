# Studio 内嵌桌面实测（2026-10-25）

本次使用本机隔离 Studio Web profile，地址 `http://127.0.0.1:18086/`，Node 22.23.4；没有修改用户原有 `~/.dsh` profile 或替换 App。页面由独立个人助理插件注册，Studio 只提供宿主与插件入口。云端目标为真实实例 `ar-20261025222804-4df266ad` 的冻结 0.1.2 镜像。

官方 DSH 登录入口消费后 303 跳转，最终地址没有鉴权参数。桌面连接使用正常 Agent key 签发的短时 ticket，经官方预发 CA 验证的网关 WSS；桌面 WS 地址不携带 query token。浏览器没有跳过证书校验或安全警告。

## 已观察到的行为

- 在 Studio 的 Personal Assistant 插件页面内看到完整 1280×800 桌面，终端和 Chromium 同时可见。
- “只读旁观”显示橙色横幅；界面活动时显示约 13 fps，空闲后显示约 1 fps。这是页面显示的帧率，不替代完整 CPU、网络及端到端性能测量。
- 关闭本次连接后，页面显示未连接，0 fps。
- 独立网关测试收到三帧二进制 JPEG，约 41 KB；首帧 3.997 秒，**未达到 ≤3 秒要求**。

## 实测发现的两个阻断问题

1. **窗口焦点未随鼠标点击切换。** 在可见 Xterm 区域点击页面坐标 `(180, 340)` 后，只读查询 X11 得到鼠标位置 `(238, 201)`，位置确实落在 Xterm 窗口，但活动窗口仍是 `Example Domain - Chromium`。因此文字到了浏览器。坐标映射本次单点没有显示错误，但尚未完成 100px 网格连续十次点击验证。候选 WM 配置此前生成空 keys 文件，必须恢复窗口聚焦、抬升、标题拖动等正常绑定。
2. **空闲回收没有关闭 WS 与客户端状态。** 桌面会话 60 秒空闲被回收后，页面出现 `DESKTOP_SESSION_NOT_FOUND`，却仍显示“你正在控制”；服务端原先只发 error 并继续轮询，自动 lease 续期可能继续存在。需要终止桌面流、停止续期、释放租约，并区分正常空闲关闭与异常断网重连。

另有只读提示问题：用户主动选择只读时，旧文案仍说“其他 Bot 正在控制”，不能据此认定真的有另一 Bot 持有租约。

上述问题正在直接修复。0.1.4 候选需要包含修复后重新打包、真构建镜像、通过正式 catalog/API 部署，再复验 Studio 内操作。已有 616c750 预览 npm 包可以用于安装与页面检查；它不代表完整桌面验收通过。当前尚未通过的网格、IME、快捷键、断网恢复、多 Bot 输入冲突、关闭后停帧、十次开关以及目标 AppArmor 验证均不口头计为通过。
