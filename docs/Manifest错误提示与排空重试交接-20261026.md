## 排空重试规范

`503 {"detail":"Server is draining"}` 由生命周期中间件在业务 handler 前返回，包含 Retry-After（默认 5 秒，客户端以实际响应为准）。新增回归覆盖 CreateAgent/DeleteAgent/RunAgent，确认 handler 调用数为 0。

客户端按 Retry-After 或有界退避排队重试，可取消并设总截止时间；保留原 InstanceId/Name/AgentId/operation 与删除策略。curl 000 表示没有收到 HTTP 响应，结果未知，先 GetAgent 对账再继续原操作；不能换新 InstanceId 盲目重建。指向旧 Pod 的 port-forward 断开后，重新连到服务/Ready Pod。400 展示字段原因后等待用户修正。

这条排空现场有直接证据；其它 503 继续按各自错误协议判断，保留之前已定位的配置与 operation 重试问题，不把全部 503 合成同一原因。
