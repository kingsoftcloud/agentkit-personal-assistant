## `(180,340) → (238,201)` 的实测解释

在隔离 Studio 加载此前 `5acbc18` 客户端，仅临时加入坐标/事件元数据探针，通过实际浏览器 DOM 测得：

```text
canvas rect: left=56, top=84, width=667, height=719
devicePixelRatio: 2
desktop: 1280×800
scale = min(667/1280, 719/800) = 0.52109375
画面左上角 = (56, 235.0625)
x = round((180 - 56) / 0.52109375) = 238
y = round((340 - 235.0625) / 0.52109375) = 201
```

这里两个轴使用同一缩放值；不能直接用 `238/180` 与 `201/340` 比较，因为页面存在侧栏偏移和上下留边。结果与历史 X11 鼠标位置完全一致。

本次布局测量时尚未建立桌面连接，canvas backing size 为默认 300×150，因此这条证据只证明 CSS 布局和历史映射成立，**不等于已验证解码后画面的 backing size、所有 DPR/尺寸变化或连续十点网格验收**。本轮未修改映射公式，也未将缩放/DPR 假设宣布为永久排除。

测量中发现隔离 Host 当前指向另一实例 `ar-20261025235707-4424eacd`，因此没有通过该页面向新目标发鼠标或键盘事件，也没有把它与本方直接 broker 的实例混为同一条链。几何记录为 `old-client-dom-geometry.json`。临时 renderer 探针已撤下，恢复最新预览包客户端；用户 profile、Host 配置均未改动。

## 仍待解释的差异

本方失败会话的 fluxbox 使用临时 `-rc` 文件，配置为 ClickFocus，但没有显式 `session.keyFile`；`HOME=/home/assistant` 目录与其 `.fluxbox/keys` 均不存在。镜像内 `/etc/X11/fluxbox/keys` 存在。这是与正常实例对照的线索；尚未证明 fluxbox 实际采用哪份绑定，更没有通过改配置使该原始循环转绿。

后续 Lead 已补充同镜像正常实例的 HOME/keys 对照，确认 HOME 状态是差异来源。本方按评审改为复制镜像完整默认绑定、仅 ENOENT 回退，见《系统默认绑定与HOME修复-20261026.md》。前文保留当时的原始失败和未确认结论，不能把后续源码回归当作旧 Pod 已升级。

暂不修改 WM。可在上述 Pod 对照 Lead 的正常实例检查实际 HOME、有效绑定、窗口层级与输入响应；两个环境的结果应并列保留。
