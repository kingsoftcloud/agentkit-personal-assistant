## 原始失败与尚未通过的门槛

1. catalog rollout 后，旧的 service port-forward 固定连在 draining Pod，首次 UpdateAgent 返回 HTTP 503 `{"detail":"Server is draining"}`，无 RequestId。切到新 Ready Pod后 GetAgent 仍是 0.1.2，未发生更新。
2. 第二次 UpdateAgent HTTP 200 / Code 400，RequestId `d4f27dd0-4653-4ecf-9d6f-2f4808cf6e4c`。runtime-service 原文 `Body Parse Failed, personal-assistant trusted host Secret projection is invalid`。`restorePersonalAssistantHost` 在恢复原有密封上下文时，要求旧 CR manifest 摘要等于新版本 cfg.ManifestSHA256；跨版本 manifest 不同即拒绝。没有放松该校验。跨版本升级仍是缺陷，本次改用正常新建通道完成 GUI 验收，不把升级算通过。
3. 0.1.4 首次本地抓帧 HTTP 400 的不稳定记录继续保留；本次新版本在上述真实 Pod 两次冷启动抓帧成功，不能倒推旧记录通过。
4. 目标 DSH AppArmor / namespace sandbox、Studio 页面内同样操作及坐标网格、IME、网络断连恢复、视觉输入延迟、真正关闭 Studio 后日程执行、PVC 重新挂载读取、重启完整恢复仍未全部验收。当前只有默认 CRI AppArmor 证据，不将其替换成目标安全结论。
