# 目标 AppArmor 下执行探测修复

预发节点 10.17.0.37 加载固定 `agentengine-dsh-sandbox-v1 (enforce)` 后，bubblewrap 的原就绪探测成功，但完整命令实际报错：

```text
bwrap: Can't mount proc on /newroot/proc: Operation not permitted
```

原探测只执行只读绑定根目录加 `/bin/true`，没有覆盖正式执行的 proc/dev 挂载和完整 namespace。修复让探测直接复用 `planCloudExecution()`，完整挂载不成功就不能选择 bubblewrap。既有 Landlock + seccomp + namespace 后端仍须通过自身实际执行探测；两个后端都不可用时继续拒绝执行。没有更改 AppArmor 策略、工具授权或租约校验。

目标 Pod 上通过显式测试环境选择 Landlock 后，未经修改的 `test/cloud-execution-linux.test.mjs` 通过：Git commit、Python/Node/Bash、SSH 客户端和技能脚本可运行，工作区外读写与元数据修改、TCP/Unix socket、并发 FD 与路径替换均被拒绝，x32 被 SIGSYS 终止，io_uring 返回 EPERM。该结果仅证明 Landlock 路径；新镜像默认选择与 GUI 仍需在目标 Pod 验证后记录。
