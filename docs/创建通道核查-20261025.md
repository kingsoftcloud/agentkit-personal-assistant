## 已确认的代码缺陷

1. runtime-service 原先只记录错误类型 `%T`。本地提交 `f5229c4` 增加原始错误与阶段，保留错误链；确定性的 BuildJob 配置错误返回 400，瞬时错误仍保留 503。
2. Server 原先遇到约定的“同一 operation 重试”503 时只请求一次。本地提交 `15ff005f` 对三种明确的重试协议做最多三次有界重试，冻结请求体、身份、operation、摘要、请求头与 request ID；其他 400/409/503 不盲目重试，取消立即停止。
3. Server 的创建 service 捕获同步错误、将记录写成 FAILED 后仍返回带 agent_id 的字典；action 只检查 agent_id，导致 Code 0。正在修复该返回边界，不能将尚未部署的修复算作线上行为。

另一个可确定的失败条件：PA 创建请求缺少模型 endpoint 时，Server 自动补 key 却不补 `OPENAI_BASE_URL`；runtime-service 会拒绝缺少 endpoint 或 key 的上下文。此前该配置错误被泛化成 503。这个条件尚不能直接认定为所报历史请求的原因。

Go `controller/agentctl` 与 `api/service/agents` 整包测试通过；Server 同 operation 重试的 19 项测试通过。runtime-service `f6df59c` 已构建并灰度至 dev API / watcher，镜像摘要 `sha256:15590932fa7e8a906ceb696dc221e738b1c516b2122a4b39a3aa89d06cafb41c`；两者滚动成功。Server 的重试修复当时尚未灰度。
