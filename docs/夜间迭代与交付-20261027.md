# 2026-10-27 夜间迭代与交付

本文按实际证据区分源码、安装包、预发实例与尚未完成的门禁。最终候选是 catalog `0.1.21`、本地插件 `0.1.4-desktop.20261027`，压缩包摘要在文末补录，不以构建通过代替云端验收。

## 本轮改动

- 聊天仍由云端 DSH 执行，与原生右侧栏中的电脑使用同一 Agent 和内部 Bot。客户端没有本地回合回退。用户无需选择“个人助理／研究助理”分类。
- 默认模型为 `deepseek-v4.1-flash-1017`；模型目录按已验证的 `text/image` 能力生成配置。`cloud_computer` 可以截取整个 X11 桌面，图像通过 DSH 附件进入模型；还可点击、双击、右键、拖拽、输入、按键、滚动、查看窗口、聚焦和启动浏览器／终端／文件管理器。
- Python、Node、Bash、Git、SSH 命令默认访问公网。没有公网开关或公网域名白名单；仍拒绝工作区越界、读取模型凭据、访问回环控制端口、内网与元数据地址。DNS 仅放行实际解析器的 53 端口。普通 Agent 的部署配置不受这项 PA 适配影响。
- 新增 `cloud_workspace` 文件读写和技能发现；助理先读取 `SKILL.md`，再用云电脑命令执行脚本。这里验证的是技能文件与脚本流程，不冒称已经接入 DSH 的原生技能索引。
- 新增 `assistant_schedule` 一次性持久云端任务。任务随云端 DSH 执行，不依赖本机 Studio 存活。
- Studio 支持附件上传和结果下载。单个文件上限 512 KiB，每条消息最多 4 个附件；附件限定当前云端会话，结果限定共享工作区，下载链接使用 `cloud-file:`。
- 回合结束立即释放工具租约；每次动作重验租约。鼠标手势使用绑定原租约的批次，接管期间中断的旧输入不重放。修复真实 DSH `tool/result` 的 `message.toolCallId` 关联，避免工具完成后进度名称消失。

## 过程中暴露并修复的问题

1. **升级后新工具仍不出现**：不是简单的 watcher 镜像问题。创建路径会投影 Bot 注册表，更新路径 `ApplyManagedRuntimeHost` 遗漏该步骤，导致旧 13 项列表保留。Runtime Service 提交 `8c68648` 修复两个 PA 更新分支，并有红灯复现与绿灯测试；dev API 已部署该提交。最终通过正式 UpdateAgent 链路投影 16 项，没有手改 CR 或 ConfigMap 绕过。
2. **工具结束后名称为空**：实际 DSH 结果事件关联键是 `data.message.toolCallId`。插件提交 `2c341f2` 修复，测试使用真实消息包络。
3. **第一次定时验收的严格断言失败**：云端任务确实执行了，但模型在指定文本后额外写入主机名和时间。失败日志原样保留。第二次明确规定只写指定字节，严格校验通过；没有修改断言来掩盖第一轮失败。
4. **一次提前推送镜像失败**：构建尚未完成时误发 push，得到 `tag does not exist`。记录保留为 `push-before-build-failed.log`；构建完成后再执行正式推送。

### 512 KiB 文件边界缺陷与修复

24 KiB 文件成功后，继续用真实 Host→Gateway→Runtime WebSocket 验证 512 KiB：上传成功，下载断开。原因是 `session.response` 共用了“最多两张桌面帧”的写缓冲（616,448 字节），而 512 KiB 文件的 base64 约 699 KiB。失败日志保留为 `file-boundary-020.log`。

提交 `034ca9e` 将会话响应与桌面写缓冲分开，独立会话固定上限 1 MiB，桌面仍保留两帧缓冲与 300 KiB JPEG 单帧上限；已经用于会话的连接不能再变成桌面连接。新增测试首次从测试客户端的历史消息中读到旧错误，修正为等待新响应后，`9f2d5dd` 完整检查 250/250 通过（另 2 项目标 Linux 专项跳过）。初次红灯日志保留，没有重写提交历史。

0.1.21 真实边界复测：512 KiB 随机二进制上传下载 SHA256 完全一致；512 KiB+1、跨会话附件引用、路径穿越均返回 400 拒绝。证据 `file-boundary-0.1.21.log`。这项没有放宽桌面帧、授权、租约或文件大小校验。
