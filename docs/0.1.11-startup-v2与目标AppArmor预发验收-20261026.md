## AppArmor 的实际边界

使用 Images 仓库已评审的固定策略与安装器，策略 SHA256：

```text
06603bfe6e086ba5ef275da86e80d82392af928dd5b40481eb4c45a2a2844f69
```

仅在 `10.17.0.37` 安装并验证。安装器只加 MAC_ADMIN，未使用 privileged/hostPID，未替换 containerd 默认 profile；节点探针实际验证 DSH/Codex 受限命令及 Host 的 TCP、Unix、proc-fd socket 后才添加节点标记。

Operator 的可信配置仅允许本方两个测试 namespace：`ar-20261026061227-3283349c`、`ar-20261026071544-e9b4f704`，未对所有租户开启。前者现已正常删除并保留云盘，后者保留供复核。

两个业务容器均从内核读取到：

```text
uid=1000
AppArmor=agentengine-dsh-sandbox-v1 (enforce)
CapEff=0000000000000000
NoNewPrivs=1
```

Operator 原先覆盖整个主容器 SecurityContext，会丢失已有 seccomp/只读根目录约束；`06bdb62` 改为在原约束副本上增强权限限制，回归先红后绿。

这证明目标 AppArmor 已执行，不再只是 CRD schema 或 containerd 默认值。namespace 的 Pod Security Admission 标签仍未设置；DSH 原生探针报告 enforcement=partial，故不宣称完整 DSH 沙箱或 A1–A14 全门通过。

## 真构建发现并修复的两个问题

**更新丢挂载。** UpdateAgent 重新投影 Host 时重建 Computer，四个 PVC 挂载随之丢失。v1/v2 ControllerRevision 对比已定位；`1d1405d` 从既有平台 PVC 重建固定挂载，不复制任意旧 sidecar 挂载。主容器一直能从原盘读到最初 canary。修复后的同一 Agent 更新后，两容器均读到原始摘要 `5ffa746d2dbc01c1c0b90dfc6af341ba2ff93d93f04c33c068c73db952587e73`，没有重写文件。PVC UID `0cad72f7-b3df-4f99-a4b5-46f8542c5a80`、PV `disk-0cad72f7-b3df-4f99-a4b5-46f8542c5a80` 不变。

该本方实例后经正常 DeleteAgent / StoragePolicy=Retain 删除，RequestId `req-20261026071946-rjdftx`；云盘仍 Bound、UID/PV 不变、ownerReferences 清空。

**bubblewrap 假就绪。** 目标 profile 下简化探测成功，但正式执行报 `bwrap: Can't mount proc on /newroot/proc: Operation not permitted`。`ff1ce4a` 让探测复用完整执行计划；失败后仅选择自身实测可用的 Landlock+seccomp+namespace 后端，不放宽 AppArmor，也不回退裸 shell。

新镜像在目标 Pod 默认配置下运行原版 `test/cloud-execution-linux.test.mjs`：1 通过、0 跳过。Git commit、Python/Node/Bash、SSH 客户端、技能脚本可用；工作区外读写、元数据修改、symlink、并发 FD/路径替换、Host proc、TCP/Unix socket 均受限，x32=SIGSYS、io_uring=EPERM。没有覆盖镜像中的实现，没有设置强制后端环境变量。

本地全量插件测试：134 项，133 通过、1 项需要显式 Linux 环境的测试跳过。Runtime Service 两个目标包测试通过；Operator 相关 116 个测试通过；Server 回归 254 通过。

- 原生 WS 两轮挂起均通过：第一轮 60009ms；第二轮从恢复首帧后计 59062ms。idle 后连续 5 秒没有二进制帧，两个空闲采样点 ffmpeg 均为 0，Xvfb/Fluxbox/xterm 的 PID 保持相同。
- 同一 session 恢复新 JPEG 为 295ms；第二个 Bot 在 idle 后可拿到租约，原 Bot 恢复控制时得到 409 并转只读，旁观输入也被服务端 409 拒绝；释放后新控制连接恢复首帧 23ms。
- 第一版采样驱动没有与远端测试程序同步，收到 idle 后即时取进程表的断言失败；增加显式检查屏障后仍保留原有全部断言，并在本 0.1.11 新 Pod 重跑通过。中间版屏障驱动漏关闭 stdin，正常功能完成后未退出，也保留为驱动失败，没有拿该次退出码报通过。
