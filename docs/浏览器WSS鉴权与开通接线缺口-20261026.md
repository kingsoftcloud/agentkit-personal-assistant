# 浏览器 WSS 鉴权与开通接线缺口（2026-10-26）

## 结论

桌面链路已采用 ticket-as-credential，不依赖浏览器发送 Authorization/X-Auth-* 或 Cookie，不需要因此改成 Studio Host WS relay。Host/Python 成功记录中的 API key 只用于签票 HTTP 请求，未带进 WS 握手。

完整地址：`wss://pa-desktop-dev.agent-pre.kspmas.ksyun.com/personal-assistant/desktop/ws`。

签票地址：`https://pa-desktop-dev.agent-pre.kspmas.ksyun.com/IssuePersonalAssistantDesktopTicket`。此处由 Host 使用 Agent API key，获得一次性、最长 60 秒的票据；默认 30 秒。浏览器只接收短时 grant。

```javascript
// 前提：Host 已有合法的账号/实例绑定；gateway 是 DSH 本地已鉴权 RPC。
const grant = await gateway.request('personal-assistant.desktop.ticket', {
  botId: 'default', mode: 'read',
});
const ws = new WebSocket(grant.wsUrl, [
  'agentkit.personal-assistant.desktop.v1',
  `agentkit.desktop.ticket.${grant.ticket}`,
]);
ws.onopen = () => ws.send(JSON.stringify({
  type: 'open', botId: 'default', taskId: `studio-${crypto.randomUUID()}`, mode: 'read',
}));
```

两个子协议是浏览器原生 WebSocket 支持的参数。票据不进 URL；Gateway 消费票据后，才向 Runtime 附加服务器签名 permit 和可信身份头。Runtime 保留 Bot/模式/租约校验。

Gateway 文档已改成中文并修正旧的 `agentkit.desktop.v1` 笔误；准确值是上面的 `agentkit.personal-assistant.desktop.v1`。完整 HTTP/1.1 curl 握手见 gateway 工作树 `docs/personal-assistant-desktop-websocket.md`。

## 本轮实测，不沿用旧记录推断

| 检查 | 观测 |

| WSS 不加额外鉴权头、不用 Cookie | ready 为 readOnly:true/controllable:false，连续收到 3 帧 1280×800 JPEG，约 41.5KB/帧 |
| 票据再次使用 | 握手拒绝 |

curl 示例仅做握手，主动限制 2 秒后 exit 28；已得到 101，不能把该限时当成握手失败。curl 未发送 open，不启动桌面。收到画面的证据来自另一次新票据的 WSS，只读、严格 TLS，帧只在内存中计算摘要，没有云端落盘。

普通 HTTP 400 说明没有进入桌面 WS 分支；可能是缺少 HTTP/1.1/Upgrade 头或中间代理未升级。没有当时的完整 curl 不能断言具体是哪一项。不要把 `ar-cloud-test` 等任意域名当成当前 pa-desktop canary 入口的等价地址。

这两轮签票/握手实测只证明协议及通道，不冒充安装版 Studio 的完整交互验收。修复前后首帧约 3949ms、2760ms 属不同运行时刻，不能归因为鉴权修复优化了冷启动，也不宣布 ≤3 秒性能验收完成。

## 配置注入是尚未完成的产品 P0

当前独立插件 Host 只从启动配置/环境读 gatewayUrl、agentId、apiKey，并在构造 gateway 时捕获；面板只有配置检查、读目录和获取票据，没有开通/绑定/安全持久化的产品闭环。剥离版 Studio 没有专用个人助理开通页，已安装 web profile 的 Studio 0.0.2 也未发现 PA 绑定桥接代码；desktop profile 的 Studio 来自应用分发而不是该 profile 的同名 node_modules，不能拿 web profile 的源码冒充其全部分发内容。

因此，在 Host 配置为空的用户安装中显示“个人助理尚未开通”是当前真实状态。成功的测试 Host 使用本方已有实例与合法凭据，不能据此声称“用户安装即可从 Studio 开通并连接”。本轮未代填用户配置、未暴露 key 到 UI、未重启用户应用。

责任归属由本方承担：开通/绑定已有实例、管理连接状态属于独立 PA 插件产品；Studio 只提供通用云凭据、部署与宿主服务，若缺通用接口则由本方在 Studio 适配，不恢复旧个人助理产品页面。

这个闭环的验收必须是：用户在插件内主动开通或选择自己的已有实例，Host 使用已认证云身份获取并托管连接凭据，页面只拿公开实例信息和短时票据，绑定完成后刷新目录/按本次用户动作连接。不能要求普通用户手填 AgentId/API key，也不能用手改 profile 的演示代替验收。该项仍未实现，不标为完成。
