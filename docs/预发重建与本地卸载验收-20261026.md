## 结论与范围

0.1.11 的双 Bot 私有状态、原会话以及 pending 日程在同一个 Agent 的 Pod 重建后恢复。
本地插件的启用、禁用、卸载通过实际 DSH PluginManager 操作；云端五类状态文件摘要前后相同。
本轮不改用户当前 Studio App/profile，不修改 catalog，不新增或覆盖候选镜像。

## 隔离本地插件生命周期

只读使用用户已安装 App 中的 DSH 0.2.1-rc.2 运行时，另建独立 DSH_HOME/profile。
从已交付的本地 tarball 解包插件并登记 profile dependency；初始 bundle 未启用。
此后调用实际 DSH PluginManager，无 mock manager：

1. listBundles 识别 installed=true、enabled=false、availability=profile。
2. setBundleEnabled(true) 返回 applied，配置中已选择插件。
3. 再次启动隔离 Host，Loader 存在 PA 插件 fiber；setBundleEnabled(false) 返回 applied。
4. 再次启动确认 PA 未加载；removeBundle 返回 applied，真实 pnpm remove 退出码 0。
5. profile dependency 和 bundles 中均无 PA；listBundles 不再返回该包。
6. CLI `--profile pa-lifecycle-acceptance --dump-config` 退出码 0，1229 行，无 PA 条目。

本机 dsh shell wrapper 仍引用不存在的 `DeepSeek Harness` 可执行文件。
验收没有修改该文件或用户 App，而是显式运行 App 的真实 `AgentKit Studio` 二进制与同包 CLI。
因此这里证明实际 DSH CLI 合成通过，不宣称该 shell wrapper 已修复。

操作前后通过独立的 Pod 通道对账：sessions、memory、messages、turns、schedules 五个 JSON 文件
SHA-256 全部一致，Runtime 与 Computer /health 均为 200。
本地卸载没有调用云端 DeleteAgent，没有删除原 Agent 或 PVC。

证据：`local-bundle-lifecycle.cjs`、`local-enable-proof.json`、`local-disable-proof.json`、
`local-remove-proof.json`、`dump-after-removal.yml`、`local-retention-proof.json`。

## 仍未替代的验收

上述隔离 Host 管理器结果不等于用户在 Studio 插件中心手动点击启用/卸载的截图证明。
完整桌面交互十项、完整 DSH 沙箱、正式分支整合仍按各自发布 gate 保持独立状态。
本轮没有发布正式版、更新用户 App 或替换已冻结的 0.1.11 镜像。
