# 桌面窗口管理器交互验收（2026-10-25）

## 变更和边界

桌面为避免 Fluxbox 冷启动向 HOME 复制默认配置，会提前创建独立的 `.fluxbox`。
原实现把 `keys` 写成空文件，丢失标题拖动、菜单和窗口切换等默认绑定。
本轮仅修改 `runtime/desktop-session.mjs`，恢复目标镜像 `/etc/X11/fluxbox/keys` 中的基础交互：

- 标题单击聚焦、抬升及激活当前标签；拖动标题或窗口边框；拖动底角调整尺寸。
- 桌面右键打开根菜单，左键隐藏菜单；标题右键打开窗口菜单。
- Alt+Tab 和 Alt+Shift+Tab 正反切换窗口；Alt+左键拖动窗口。
- 保持 ClickFocus，显式设置 `clickRaises:true`。Ctrl+C、普通 Tab、Esc 交给应用。

不通过 xdotool 的 windowfocus/windowactivate 在输入前强行选窗口。
也没有增加 `OnWindow Mouse1` 绑定：Fluxbox 1.3.5 的 `buttonPressEvent` 在命中绑定后直接返回，
而原生正文点击路径包含 `ReplayPointer`，会把点击继续交给应用。
不能为了聚焦而吞掉网页控件或终端的正常单击。

依据为目标镜像的默认 keys，以及官方 [keys 说明](https://fluxbox.org/help/man-fluxbox-keys/)、
[窗口管理设置说明](https://fluxbox.org/help/man-fluxbox/) 和固定 Release-1_3_5
[Window.cc](https://github.com/fluxbox/fluxbox/blob/b023c124a8c2b68597b26bc0721b09a7875ccece/src/Window.cc#L2323)。

## 失败记录和验收方法修正

原始记录均保存在 `.artifacts/desktop-focus-20261025/`：

- `baseline-result.json`：原空 keys 正文焦点对照，六次通过。
- `image-fluxbox-default-keys.txt`：从目标镜像读取的默认绑定。
- `first-title-coordinate-failure.json`：首次探针错用 xdotool geometry，落到正文，报 `titlebar drag failed`。
- `second-stack-check-failure.json`：焦点正确但 EWMH stack 断言失败。
- `third-native-interaction-failure.json`：保留单次跳变 motion 的标题拖动失败。
- `fixed-result.json`：修正探针后的完整正例，包含实际坐标、窗口族、菜单映射、输入 canary 和有效配置。
- `verify-focus.mjs`：可重放的真实 broker 驱动；`cleanup.json` 为临时进程回收核查。

标题位置以 `xwininfo` 的绝对客户区坐标为准；首次 xdotool geometry 在该装饰窗口下额外增加了
24px，导致点错位置。真实拖动由多次连续 motion 构成，不能只发一次跳变后立刻抬起。
Fluxbox 该版本的 `_NET_CLIENT_LIST_STACKING` 实测没有随每次抬升更新，仍保留原值作为证据，
改用两窗重叠点的真实 X 窗口命中验证遮挡次序，没有把失败断言改成无条件通过。

本轮不构建新 tar、不更新镜像锁或 catalog，由主任务收齐输入修复后统一重打制品。
