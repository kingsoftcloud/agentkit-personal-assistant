# 云端回合、模型配置与 manifest 验收

2026-10-25 在预发通过真实 Server API 创建并验证了个人助理 0.1.2。关闭本机 Studio 后，云端 DSH 调用真实用户模型并完成回合。本记录不代表网关桌面、Studio 内嵌 GUI、专用 deny AppArmor 或全部工具验收完成。

## 两个问题的结论

云端 profile 是纯 DSH web 组合加独立个人助理插件，实际组合中 `hasStudio=false`、`hasPersonalAssistant=true`。Studio 白名单修改已撤销，未部署。环境变量不会让未加载的 Studio 模块参与启动。

模型由个人助理镜像的 `runtime/prepare-dsh-profile.mjs` 准备。脚本读取 `manifest.model`、平台注入的 `OPENAI_BASE_URL`，生成 `DSH_HOME/platform-model.patch.yml`，设置 `llm-pi-ai` provider 与 `agent-default-model`；入口 CLI 通过 `--patch` 加载。模型凭据只以 `apiKeyEnv: AGENTKIT_MODEL_API_KEY` 引用。默认模型服务读取配置，并不自行从选模环境变量合成 provider。

真实 Pod 的有效组合为：

```json
{
  "defaultModel": {"provider":"personal-assistant-cloud","model":"glm-5.1"},
  "provider": {
    "baseURL":"https://kspmas.ksyun.com/v1",
    "api":"openai-completions",
    "apiKeyEnv":"AGENTKIT_MODEL_API_KEY",
    "modelIds":["glm-5.1"]
  }
}
```

该实例显式指定模型入口；key 由 Server 沿现有流程为当前用户创建 AICP key，再由 Runtime Service 投影为 Secret。修复了重复投影把真实模型 key 覆盖成 runtime token 的问题；当前实测两者不同，未输出密钥。

manifest 也不是遗留的无效输入。**实际消费它的是个人助理自己的准备脚本，不是 Studio admission。** 脚本在 DSH 启动前读取实际文件字节，核对 SHA-256，解析 YAML，验证 framework、artifact_type、runtime 名称/版本及模型字段，再生成模型 patch。这将挂载的 canonical manifest 与控制面选择绑定；不等同于消费或校验全部 Studio 资源声明。

真实 Pod 中，实际文件 SHA、环境变量和启动日志均为：

```text
8ead2ae42308d0acb127b181b9b90318f2650e311a1f0d2b85181ea732fc622a
```

在 Pod `/tmp` 中对独立副本添加字节、保持原摘要，运行同一个准备脚本：退出码 1，`MANAGED_MANIFEST_DIGEST_MISMATCH`，未写模型 patch。真实 manifest/profile 没有被修改。

当前 `manifest.prompt` 尚未投影到 agent 的系统提示词，此项仍需补齐；不能将本次摘要与模型验证描述成全部 manifest 语义均已实现。

## 六步证据与复核命令

以下命令在个人助理项目目录执行。重复运行验证脚本会创建新的验收会话，并短暂申请和释放租约。

```sh
export KUBECONFIG="$HOME/.kube/config-b56be622-ca25-463a-ba21-55f9070c83ca"
NS=ar-20261025215911-7ef6c6f5
POD="$NS-0"
```

本次使用受信内部 Server API，经过 Server → Runtime Service → Operator → AgentRuntime，没有直接创建 Pod。此路径不等同于公开网关鉴权验收。

```sh

  port-forward svc/agentengine-dev 19082:8081
```

```sh

  -H 'Content-Type: application/json' \
  -H 'X-Ksc-Account-Id: 2000003485' \
  -H 'X-Ksc-User-uuid: No1qNME1QqKQhMmANC4xcQ' \
```
