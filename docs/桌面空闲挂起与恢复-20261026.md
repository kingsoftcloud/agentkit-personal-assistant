# 桌面空闲挂起与恢复（2026-10-26）

## 行为目标

Lead 的 0.1.5 实测：保持面板连接但 75 秒无输入，原 60 秒策略结束会话，用户须手动重连；回收后的 ready/首帧为 922/1146ms，热态为 759/1069ms。这是旧版本的真实行为与测量，不用新代码覆盖原报告。

本轮将新版本的空闲改成挂起：默认无输入 60 秒后停抓帧、停续租，释放桌面自动申请的控制租约，保留逻辑会话、Xvfb、窗口管理器、终端和浏览器窗口。用户点击、滚轮、按键或文字输入才发起恢复；单纯移入鼠标、切回标签页不会自动抢控制。恢复前重新取得租约，冲突返回 409 并恢复为只读旁观；缓冲输入此时丢弃，不发给其他 Bot 控制的电脑。

挂起记录默认保留 15 分钟，以限制断线后无人清理的记录。期间窗口与终端进程保留；保留期到期后的会话仍按已结束处理，不能自动“复活”。面板关闭、显式断开、租约失效、错误 404 与 Pod 重启继续按原终止语义清理。

只撤销桌面自己申请的租约；显式绑定的外部任务租约由该任务管理，桌面挂起不能中断外部任务，也不能宣称这种任务的控制权已经释放。

## 协议与实现边界

- Computer 的会话元数据明确返回 `idleMode: suspend`、`idleTimeoutMs` 与 `idleRetentionMs`。仅协商到该模式的 Runtime 使用新状态机，旧 Computer/Runtime 保持原有结束语义。
- Computer 以 `DESKTOP_SESSION_IDLE / 409` 区分挂起与真正的 `DESKTOP_SESSION_NOT_FOUND / 404`。`/broker/desktop/idle`、`/broker/desktop/resume` 检查原会话 Bot/task 归属；控制恢复还须通过当前有效租约校验。
- 挂起先串行释放已按下的键和鼠标，再释放桌面自动租约；旧输入在队列真正执行前再次核对会话与租约。共享采集进程仅在没有其他活跃观察会话时停止，单个面板挂起不能中断其他面板的观察。
- Runtime 在同一已鉴权 WS 上发送 idle；暂停抓帧和续租，保留 sessionId。收到明确用户活动的 resume 后重新取租约、恢复会话。只读签名授权不能借 resume 升级为控制。
- 抓帧、解码与续租均有状态代次检查，挂起前在途结果不能重新打开控制态。恢复失败的新租约会清理，恢复期间断线的晚到租约同样清理。
- 客户端保留最后一帧并覆盖“已空闲”提示，帧率归零；恢复期间最多缓冲32个输入，收到可控 ready 后才按序发送。只读/冲突时不发送缓冲输入；中文组合输入只入队一次。恢复后的第一张画面仍有12秒截止。
- 空闲时网络断开不后台重新申请控制；下一次明确操作才重新连接。正常关闭、已结束会话仍不自动重连。

## 当前验证

先以回归复现“空闲删除会话”和“面板无法恢复”，再补充同会话/新租约、只读签名授权拒绝升级、409不抢占、恢复期间断线、外部任务租约不撤销、中文/emoji首段缓冲、旧帧不激活控制及保留期到期测试。

真实桌面源代码覆盖验证使用原镜像加只读挂载的新模块，没有改变默认60秒策略、租约/沙箱校验或图像上限：60194ms进入idle；随后5秒无新帧，另一个Bot成功取得租约；恢复控制冲突为409并保持原会话只读；只读重放输入409；恢复控制新通道首帧350ms。挂起前后Xvfb、终端PID一致，挂起时ffmpeg=0。报告在 `.artifacts/desktop-idle-suspend-20261026/smoke-pair-result.json`。该数据是本地双容器源代码覆盖验证，不冒充不可变新镜像、预发或Studio内实拍。

此行为需要新的 Runtime 与 Computer 共同部署，以及重建后的本地客户端。仅换本地包不会改变0.1.4/0.1.5云端的60秒结束语义。旧镜像和Lead的实例、脚本、profile与App保持原样。

## 0.1.8 不可变镜像与预发结果

两份产物分别打包两次且摘要一致，真实构建、推送两个镜像，并追加 dev catalog 0.1.8。由真实 CreateAgent API 创建 `ar-20261026050838-45a7eaec`，Pod 恰好两个普通容器，均 Ready、重启次数为0；未借助裸 Pod 或旁路控制面。

- Pod 内真实 WS：60031ms进入挂起；随后5秒无帧；Xvfb、fluxbox、终端PID保持一致，ffmpeg为0；同一会话重新取得租约后，首张新的二进制JPEG耗时224ms。
- 第二次挂起后，另一Bot成功取得控制租约。原会话恢复控制返回409，并以同一sessionId恢复只读；只读输入重放仍被服务端409拒绝，没有抢占另一Bot的租约。
- 真实网关 WSS：60907ms进入挂起，连接保持，5秒无帧；同一只读会话恢复后首张新JPEG耗时341ms。严格TLS、一次性票据子协议通过；WS没有自定义鉴权头、cookie或query token。
- 冻结源码在新Runtime镜像中执行全量测试：129项，128通过、0失败、1项需要显式环境的真实Linux沙箱测试跳过。没有跳过GUI、窗口管理器或空闲恢复断言。
