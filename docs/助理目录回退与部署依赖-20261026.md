# 助理目录回退与部署依赖（2026-10-26）

## 问题与范围

0.1.2 Runtime 不实现 bots.list，旧面板把它当成目录错误并清空选择项，使已经开通且鉴权正常的用户无法进入桌面。这次按产品要求提供固定的默认助理回退，不恢复旧 assistant/* 操作或旧个人助理产品代码。

Host 为 __directory__ 申请独立只读票据，返回给客户端的目录仍只含 botId/displayName；系统提示词、工具策略、凭据不进入页面。

## 回退规则

- 已确认 Host 配置完整后，旧 Runtime 明确返回 DESKTOP_MESSAGE_UNSUPPORTED，或已建立目录 WS 后出现临时故障/超时，显示 default / 默认助理，并提示“暂时无法读取助理列表，已使用默认助理”。
- 已知 HTTP 5xx 的目录升级失败可以回退。401/403、策略关闭 1008、无效票据、格式错误及未完成握手的不透明错误均不回退，避免把授权失败显示成普通目录故障。
- 配置未就绪不回退。成功返回的空目录是有效结果，不伪造 default。
- 默认项只供用户主动选择，不自动打开桌面。连接仍重新申请该 Agent/default 的普通票据，云端继续校验 Bot 存在、票据和控制租约；回退不授予控制权限。若真实运行时没有 default，连接照常被拒绝。
- 未连接时提供“刷新助理列表”。目录恢复后用真实结果覆盖默认项并重新选择有效助理；已有桌面连接期间不提供会中刷新，避免一次目录查询意外释放当前租约。

Host 将旧协议不支持、鉴权拒绝、临时不可用分成不同错误码。Node ws 的 unexpected-response 保留 HTTP 拒绝状态并释放响应；浏览器/原生 WS 无法判断握手错误原因时按不可回退处理。

## 部署依赖与负责人

| 部件 | 本次目录功能要求 |

| PA Runtime | 0.1.4 已实现 bots.list，完整目录需要该镜像；0.1.6 复用相同 Runtime。0.1.2 可通过本次默认项回退连接 |

## 测试证据

先复现缺少回退/错误分类的 7 项失败，再验证面板从默认项主动连接、鉴权失败不回退、刷新后恢复真实目录、握手 HTTP 401/403/503 分类与不透明错误拒绝回退。

固定 Node 22.23.4 全量测试 110 项：109 通过、1 跳过、0 失败。跳过的是需要显式环境的真实 Linux 沙箱测试。评审列出的入口文案、网络重连/控制冲突、HTTP 会话隔离与定时任务 bridge 三项均通过；没有通过删除断言或禁用校验让它们通过。

该回退状态机目前以协议夹具自测；不把它算成旧 0.1.2 上已经完成一次真实 Studio GUI 操作。既有真实 Pod、租约、模型回合及 WSS 性能证据见《0.1.6默认绑定修复与真实Pod验收-20261026.md》，首帧容错与性能目标分开记录。
